# md-agent v1.9.0 — field audit from two real runs (2026-09-05)

Two review runs launched detached from a Claude session with `--launch`, watched with `--watch`,
one on `arsenal` (small repo, no CLAUDE.md) and one on `forge-api` (2037 C# files, a 70 KB CLAUDE.md).
Same team shape on both: a cheap sweeper behind its own verify, an opus reviewer behind the run verify,
a sonnet challenger with `verify: false`; worktree isolation; USD soft/hard budgets; `autoComplete`.
Every number below is from `runs/<dir>/log/<seat>.jsonl` (per-call `message.usage`, `result`
envelopes, the `{"md":"turn"|"end"}` markers) reconciled against the `--watch` digests.

| | arsenal | forge-api |
|---|---|---|
| wall clock | 21 min | 17 min |
| turns (orch / seats) | 13 / 12 | 11 / 14 |
| digest Σ | $8.58 | $15.87 |
| trace Σ | **$11.67** | $15.87 (+1 unbooked turn) |
| tokens (digest) | 15.7M | 24.9M |
| seat first-call prefix | 11k–16k | **39k–50k** |
| orchestrator prefix / turn cost | 16.5k / $0.04–0.08 | **45k–48k / $0.15–0.20** |
| skills loaded per seat | 53 | 53 |
| verify bounces | 0 | 2 (both on interim replies) |
| turn errors | 1 (`error_max_budget_usd`) | 0 |
| deliverable | verified, fully challenged | verified, 10 of 27 findings challenged |

Both runs produced a real deliverable on a branch that the completion gate verified. The harness held:
isolation held for every claude seat (a seat's file never appeared in the main tree), per-seat verify
ran only in the seat's own worktree, `verify: false` seats were never judged, the soft line was hit and
announced on both runs, recycle-by-size fired exactly once on real resident context, preflight refused
an out-of-quota provider before any spend, and `--stop`-free teardown listed branches with PASS/FAIL.
What follows is what cost money or quality anyway, ordered by what it cost.

## What is confirmed fixed since the 09-04 / 09-05 lists

- **E1 recycle-by-size** — fired once on the forge-api reviewer at 211k resident context after 6
  turns (`[role:reviewer] resident context is 211k tokens (≥ 200k) — recycling`), not after every turn.
- **E4 verify on unchanged workspaces** — the challengers (`verify: false`) and untouched seats were
  never verified; per-seat `verify` on the sweepers ran in their worktrees only.
- **E7 (half)** — seats run with 8 tools and no MCP (`init.tools=8, mcp_servers=[]`); the
  orchestrator with 3 tools and 0 skills. Arsenal seat prefix 11k–16k vs the 22.7k measured on 09-05.
- **E8 seats know the verify command** — both reviewers ran the exact verify regex on their own
  report before replying.
- **E9 per-turn caps** — `turnBudgetUsd` bound a runaway opus turn at $3.09 (see F3 for the cost of
  how it was reported).
- **F1 (09-04) isolation for claude seats** — verified: the sweeper's grep ran against the main
  checkout path (read-only) but its file landed only in `workspaces/sweeper`, the main tree stayed
  clean, and the run verify ran there.
- **Quota preflight** — `[preflight] probing agy… FAIL … Individual quota reached` refused the launch
  before a run dir existed. One nit: the 300-char tail cut the reset time off the message.
- **`--watch` / `--status` / `--once`** — the digest-on-change stream carried a run end to end from a
  Claude session with no console; the umbrella frame was usable as the user-facing status.

## Findings

### F1 — Under worktree isolation, seats cannot see each other's artifacts, and nothing tells them how

**Observed on both runs; the single largest cost.** The sweeper wrote its tables into its own
worktree; the orchestrator dispatched the reviewer with "use the sweeper's tables"; the reviewer
replied "the sweep file isn't in my worktree" and **re-derived table B from scratch on opus**. The
challenger was dispatched to verify a report that existed only uncommitted in the reviewer's worktree;
three challenger turns (`$0.09`, `$0.02`, "no work to do this turn") and four orchestrator turns went
to discovering that, asking the reviewer to commit, and re-dispatching. On forge-api the opus reviewer
worked it out itself ("the sweeper's branch is reachable from my worktree's shared object store —
reading their sweep doc from git") but only on its sixth turn.

Root cause is the CLI, not the orchestrator: a claude seat cannot read outside its cwd, and md-agent
never commits on a seat's behalf, so a verified reply's artifact is invisible to every other seat
until a human or a lucky orchestrator asks for a commit. The mandate says where the seat's workspace
and branch are (E8) but not where the *other* seats' are.

- **Smallest fix (either is enough):** (a) after a verify-PASS reply under isolation, auto-commit the
  seat's workspace on its branch (`git add -A && git commit -m "md-agent: <seat> turn N"`) and put
  `branch@sha` in the ledger's artifact line and in every dispatch that references that artifact; or
  (b) pass `--add-dir <runDir>/workspaces` to every claude seat so sibling worktrees are readable, and
  say so in the mandate ("other seats' work: `../<seat>/…`, read-only").
- **Cost here:** ~$1.50 of orchestrator+challenger turns on arsenal, an unknown share of the reviewer's
  $3.09 re-derivation, and on forge-api the sweeper's $2.99 of tables reached the reviewer only after
  the soft line.

### F2 — `claimsDone` bounces interim status, so a seat working in slices is punished for reporting

`orchestrator.ts:2024` treats any reply containing `done|complete|finished|…` without a negation as a
completion claim. The forge-api reviewer's "PART A slice 1 done. Notes in `docs/_review-notes-partA.md`
(not the deliverable)" was bounced twice with the run verify's output; its own words on the third
turn: "the check ran against a file I hadn't written yet — I'd been reporting slice status, not
done. Writing the deliverable now." That is the TURN DISCIPLINE clause (one slice per turn, report)
colliding with the bounce heuristic. Each bounce cost a reviewer turn (`$1.44`, `$0.87`).

- **Smallest fix:** make the completion claim explicit — the mandate asks the seat to end a reply
  that is ready for the run verify with a literal token (`[VERIFY-READY]`); `claimsDone` matches only
  that. Interim replies then get the verify result *attached* (the documented path), never bounced.

### F3 — A turn that hits `turnBudgetUsd` is reported as a generic crash, and its cost vanishes

The arsenal reviewer's second turn ended `error_max_budget_usd` at $3.09 / 36 calls. The CLI's
`result.subtype` says exactly that; md-agent logged `[role:reviewer] error: Error: claude exited 1`
and posted `[ROLE ERROR] … could not complete this turn … Re-dispatch if it should retry`. Three
consequences: the orchestrator treated it as "tool exited 1" and asked the seat to check its file; the
seat's partial work (angles 1 and 2 were on disk) was unknown to everyone until the seat said so; and
**the $3.09 was never booked** — digest Σ $8.58 vs trace Σ $11.67, a 36 % under-report on the run
that hit its soft line at "$8.54".

- **Smallest fix:** in `claude.ts`, read `result.subtype`/`errors` on a non-zero exit and raise a typed
  error; in `role.ts`, book `result.total_cost_usd` regardless of exit code and write the outbox note
  as "turn budget of $N reached after K calls; work on disk may be partial; re-dispatch with a smaller
  ask". Same for `turnTimeoutSec`.

### F4 — The project's CLAUDE.md rides in every call of every seat *and the orchestrator*

forge-api's 70 KB CLAUDE.md put the seats' first-call prefix at 39k–50k tokens (arsenal: 11k–16k)
and the orchestrator's at 45k–48k (arsenal: 16.5k). Every one of the forge-api orchestrator's 11 turns
cost $0.15–0.20 against $0.04–0.08 on arsenal for the same one-call shape; the sonnet sweeper's first
sweep read 1.6M tokens across 22 calls, ~70 % of it that prefix. There is no launch-config control for
it, and the orchestrator — which coordinates and never touches the code — has no use for it at all.

- **Smallest fix:** `--setting-sources` (or the CLI's equivalent for project instructions) off for the
  orchestrator unconditionally, and `roles[].projectInstructions: false` for seats that do not need
  it; print the measured first-call prefix per seat at launch so the user sees it.

### F5 — Seats still load every skill (53 here)

`noSkills` is set for the orchestrator, planner and journey handshake only (`orchestrator.ts:152,279`,
`plan.ts:186`, `journey.ts:412`). Every seat's `init` listed 53 slash commands. This is the other half
of E7.

- **Smallest fix:** `--disable-slash-commands` for seats by default, `roles[].skills: true` to opt in.

### F6 — The orchestrator dispatches a consumer before the producer it just asked has replied

Arsenal: at 19:13:34 it dispatched "reviewer: commit your report" and "challenger: fetch the reviewer's
branch" in the same turn; the challenger ran first and found nothing (`$0.02`), then again at 19:19:39
after a second identical pair. The prompt already says seats coordinate through the orchestrator; it
does not say "when you ask seat A for something seat B needs, dispatch B on A's reply, not now".

- **Smallest fix:** one sentence in the orchestrator prompt, plus a ledger convention: a dispatch that
  depends on another seat's pending reply is written as `[after <seat>]` and held.

### F7 — The completion gate races an in-flight seat turn; that turn's work is ungated and unbooked

forge-api: the orchestrator requested completion at 19:22:18 while the reviewer's eighth turn (started
19:22:08, a fresh session after recycle) was running. The gate verified `d7efca45`, the run ended at
19:22:38, and the reviewer committed `c9e318bd` (three new findings) at **19:25:06** — after RUN END.
The branch now carries a commit the gate never saw, the trace has no `end` marker for that turn, and
its cost is absent from Σ. The teardown's "1 file changed, 1 commit" line was stale by the time the
seat exited.

- **Smallest fix:** on completion, wait for every busy seat's turn to end (or cancel it and say so)
  before running the gate, and run the gate on the branch head it prints. Book the turn either way.

### F8 — The challenger's verdicts were lost at the soft line; the report shipped with a struck finding

forge-api: the challenger's second pass struck M3 (the schema already has the filtered unique indexes
the finding says are missing) and corrected an M1 citation at 19:21:36; the orchestrator dispatched
the reviewer to apply them at 19:22:18 and requested completion in the same turn; the run ended before
the reviewer acted. The final report contained M3 unmarked, and its coverage section did not say which
findings the challenger had reached (H1–H2, M1–M7, L1 — 10 of 27). Reconciled by hand afterwards
(`85262ddb` on the reviewer branch).

- **Smallest fix:** the completion checklist in the orchestrator prompt gains "every reviewer/
  challenger verdict in the ledger is applied or explicitly listed as open in the deliverable"; the
  ledger's artifact line carries "challenged: N/M".

### F9 — Soft-budget "winding down" is a note, not a behaviour, on a run with work in flight

arsenal: soft $8 hit at $8.54, one small finishing turn, ended at $8.58. forge-api: soft $12 hit at
$12.01; the orchestrator then dispatched two more reviewer turns and a challenger turn and ended at
$15.87 (+32 %). Both ended below hard, so the contract held, but "winding down" meant different
things on the two runs and the user cannot predict which.

- **Smallest fix:** define it: after soft, the orchestrator may dispatch only turns that finish the
  deliverable (commit, apply verdicts, gate) and must say in the ledger why each post-soft turn was
  necessary; anything else waits for the user.

### F10 — Detached runs skip the journal offer silently

Neither `run.log` mentions journals. With no TTY the run-end prompt is skipped, correctly, but nothing
says so or how to push later.

- **Smallest fix:** log `journal: no TTY — push later with md-agent (Journals → push) or set
  journal.ask=false`.

### F11 — The `--watch` digest's `last:` line is the turn's *first* text block

The arsenal reviewer's `last:` read "I'll start by mapping the adapter and sim source files" for its
whole 6-minute first turn while its tool counts climbed to Read×13 Bash×12; the challenger's read
"The reviewer's commit hasn't landed yet" three digests after it had. `on:` was live; `last:` was not.

- **Smallest fix:** take the latest `text` block of the current turn, falling back to the previous
  reply only when the turn has none yet.

### F12 — Small things seen once

- A haiku sweeper counted `[Fact]` attributes as the test count (157 vs the 160 `dotnet test` reports,
  271 vs 340 for the sim) and flagged "drift"; the opus reviewer spent part of a turn refuting it. A
  mechanical seat's method belongs in its table header so the consumer can discount it without
  re-deriving. Not an md-agent bug; a brief-writing lesson: tell the cheap seat *how* to count.
- The preflight message truncates at 300 chars from the tail; the useful part (`Resets in 143h0m19s`)
  survived only by luck of position.
- `up_probe`-style launches from a script leave `runs/once-over.log` in the project; `runs/` needs a
  `.git/info/exclude` entry per project or md-agent should write it.
- The orchestrator's ledger artifact lines were good enough to use as the run's summary verbatim;
  keep that.

## Suggested order

F1 (artifact visibility) and F7 (gate race) first — both corrupt the run's own accounting of what it
produced. Then F3 (unbooked/misreported turn errors) and F2 (bounce heuristic), which together made the
reviewers' worst turns. F4/F5 are the prefix money: on a repo with a large CLAUDE.md they are the
difference between a $16 and a roughly $9 run. F6/F8/F9 are orchestrator-prompt sentences. F10/F11
are cosmetic.

## Model-tiering experiment (same evening, same goal, same budgets)

Five runs of the arsenal once-over (3 angles: correctness, doc drift, config drift; haiku sweeper,
sonnet read-only challenger). Quality = findings that match the opus baseline's 20 challenger-verified
findings, plus valid new ones; false = a finding the run's challenger passed that the tree refutes.

| Run | Reviewer shape | Cost | Turns | Re-read | Baseline hits | New valid | False passed | Highs found |
|---|---|---|---|---|---|---|---|---|
| A | opus, 3 angles (pre-fixes) | $11.67 | 26 | 20.4M | 20/20 | — | 0 | 3/3 |
| B | opus, 3 angles (post-fixes) | $9.78 | 19 | 12.5M | 19 | 1 | 0 | 3/3 |
| C2 | **opus correctness + sonnet drift** | **$5.00** | 9 | 7.4M | 8 (7 correctness, 1 drift) | 3 | **1** (drift "missing test class" — it exists) | 2/3 |
| D2 | sonnet, 3 angles | $4.57 | 22 | 13.2M | ~2.5 | 1 | 3 (two test-count claims A struck; "example predates B169" — sample is there) | 0/3 |
| E2 | sonnet correctness + sonnet drift | $3.71 | 21 | 6.9M | 3 | 2 | 1 (Grant:BaseUrl "undocumented" — deliberate per A) | 1/3 |

What it says:

- **Opus correctness is stable and cheap in one seat.** C2's opus correctness turn ($2.33, one turn)
  found 7 of A's 10 correctness findings plus two valid new ones (the forge sources bypass the
  `JoblistEnabled` guard and fault the tick loop; `_lastError` never clears). It missed C1 (grant
  outbox IO under the tick lock) and C4.
- **Sonnet as a reviewer finds 15–25 % of what opus finds** and rates what it finds wrongly (D2 called
  the unread `offerSource` block High and the join race Low). All-sonnet cost $4.57 for ~2.5 hits.
- **The sonnet drift seat found 1 of 10 drift/config findings.** The drift angles are not mechanical
  enough for sonnet: D1 (§7's M2 overclaim), D2 (the contract's `_seen` invariant), E1 (a retired
  config-selected store still documented) all need the same judgement as correctness.
- **A sonnet challenger passes false positives.** It verifies that a citation's line says what the
  finding quotes; it does not catch a wrong conclusion (a file "missing" that exists one directory
  over, a key "undocumented" that the config comment explains). The opus reviewer in A struck exactly
  these itself. Zero strikes from a sonnet challenger is not zero false positives.
- **Cost per valid finding:** A $0.58, B $0.51, C2 $0.45, E2 $0.74, D2 ~$1.30.

Recommendation: **opus for every judging angle; split angles across parallel opus seats for
wall-clock, not for cost; sonnet only for verification-shaped work with a mechanical check; the
challenger on opus when the deliverable's conclusions matter, sonnet when only the citations do.**
The tiering saving is real only where the split-off work is mechanical.

Wasted on the way: $3.56 — three runs launched with a verify command that an unquoted heredoc had
gutted (`test  -ge 10`). **Fixed the same evening:** md-agent now dry-runs every verify command at
launch, refuses a shell error or a malformed comparison before the run dir exists, and prints the
dry-run's exit for a well-formed one.
